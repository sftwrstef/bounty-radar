## Predeclared sink-first question

Does the current public REST or AJAX review-submission route reach a stored review write, and is any ordinary-user-controlled value then used in an admin HTML sink or dynamic SQL without appropriate escaping/sanitization or parameterization? First identify the route, permission checks, and write/query sink; only then select a concrete field. Stop quickly if the route is blocked for ordinary users, the write is not reachable, or the candidate sink is demonstrably escaped/parameterized. An isolated local diagnostic is justified only if an exploitable code path survives this source trace. Time box: 20 minutes; do not audit the whole plugin.

## Source trace and cheapest falsifier

1. The [REST submission controller](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Controllers/Api/Version1/RestSubmissionController.php) registers `POST /submissions` (lines 35–51). Its permission callback (17–25) checks a valid `submit-review` mutex, rather than a WordPress role. Submission (28–32) constructs `CreateReview`. This is a conditional public route: the valid form token and the downstream form validators still matter; no unauthenticated request was sent.
2. `CreateReview::handle()` [validates before creating](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Commands/CreateReview.php) (69–74, 191–195, 206–216). `ReviewManager::createRaw()` [writes the review with `wp_insert_post`](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Database/ReviewManager.php) (117–142), including submitted content/title and metadata. Thus the conditional submission path genuinely reaches a stored write.
3. Only after confirming that write did I select the review author's **name**. The [admin column handler](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Controllers/ListTableColumns/ColumnValueAuthorName.php) returns `$review->author` directly for non-account reviews (12–21), and the [list table controller](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Controllers/ListTableController.php) echoes column values (315–326). This is a credible HTML sink to challenge, not itself proof of XSS.
4. The path is source-killed upstream: [CreateReviewDefaults](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Defaults/CreateReviewDefaults.php) assigns `name => user-name:current_user` (49–69), and `CreateReview::setProperties()` applies `restrict()` to request values (257–260). [DefaultsAbstract](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Defaults/DefaultsAbstract.php) runs `sanitize()` after restriction (156–166, 337–350). [SanitizeUserName](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Modules/Sanitizers/SanitizeUserName.php) decodes entities, strips tags, removes all characters outside a narrow name allowlist, then calls `sanitize_text_field` (45–59). When a review object is hydrated, [ReviewDefaults](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Defaults/ReviewDefaults.php) applies an additional text sanitizer to `author` (41–58), through [Review](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Review.php) construction (78–92). Ordinary submitted markup therefore does not survive to that raw admin echo on the traced path.
5. Title/content also have explicit text/text-multiline sanitizers in `CreateReviewDefaults` (55, 67). The [text sanitizer](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Modules/Sanitizers/SanitizeText.php) and [multiline text sanitizer](https://plugins.svn.wordpress.org/site-reviews/tags/8.3.4/plugin/Modules/Sanitizers/SanitizeTextMultiline.php) decode entities and strip tags before WordPress text sanitization. I did not pursue those as an alternative field after the sink-first stop.

**Result:** no local runtime test was run; no exploit, severity, duplicate, or payout claim. This falsifies only the ordinary submission → review-author-name → admin list-column stored-XSS hypothesis in the unmodified 8.3.4 code. It does not exhaust Site Reviews, optional extensions, or unrelated SQL paths. Any filter/plugin override that changes these sanitizers would be a separate configuration and is not assumed here.
